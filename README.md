# 個人影片編輯器

依 [video-editor-spec.md](video-editor-spec.md) 實作的 Windows 影片編輯工具（C# / WPF）。

開發者請先看 [專案結構導覽](docs/project-structure.md)。

## 執行

需要 .NET 10 SDK，以及 `ffmpeg.exe` 與 `ffprobe.exe`（放在程式目錄的 `tools\ffmpeg`，或加入 PATH；PATH 裡的相對路徑項目會被略過，要用完整路徑）。程式啟動時會把實際使用的 FFmpeg 路徑與版本寫進紀錄，並固定顯示在視窗最下方狀態列的右側（滑鼠移上去看完整路徑）。FFmpeg 必須含 libx264 與 libx265。

```bash
dotnet run --project src/VideoEditor.App
```

第一次啟動時 LibVLC 要掃描外掛，視窗可能過一段時間才出現。

```bash
dotnet test
```

多數測試會用 FFmpeg 當場產生短片再實際匯出，標了 `Category=Integration`。沒有 FFmpeg 時，只跑不需要它的測試：

```bash
dotnet test --filter "Category!=Integration"
```

GitHub Actions（`.github/workflows/ci.yml`）會在 Windows 上建置並執行測試，推送到 `main` 與每個 pull request 都會觸發。

## 產出 exe（發佈）

在 Windows 上執行下列指令，產生不需另外安裝 .NET 的資料夾版本：

```bash
dotnet publish src/VideoEditor.App -c Release -r win-x64 --self-contained true -o publish
```

- 執行檔是 `publish\VideoEditor.App.exe`，LibVLC 的原生檔會一起放在 `publish` 裡（`libvlc\win-x64`），所以要整個資料夾一起搬移或壓縮，不能只複製 exe。
- `ffmpeg.exe` 與 `ffprobe.exe`（含 libx264、libx265）不會被打包，請放到 `publish\tools\ffmpeg`，或讓使用者的 PATH 找得到。
- 不建議加 `-p:PublishSingleFile=true`：LibVLC 要掃描外掛資料夾，無法包進單一檔案。
- 只支援 64 位元 Windows（專案已關閉 x86 與 ARM64 的 LibVLC）。
- 若只想給已安裝 .NET 10 桌面執行階段的電腦使用，可改成 `--self-contained false`，檔案會小很多。

## 操作

| 按鍵 | 功能 |
|---|---|
| 空白鍵 | 播放／暫停 |
| J | 倒帶（往回播放）；倒帶中再按加速為 2×、4×、8× |
| L | 播放；播放中再按快轉為 2×、4×、8× |
| K | 暫停 |
| ← / → | 前一格／後一格 |
| I / O | 設定入點／出點（素材模式） |
| Delete | 刪除選取的片段 |
| S | 在時間軸播放頭分割選取的片段（時間軸預覽） |
| Page Up / Page Down | 跳到上一個／下一個剪輯點 |
| Ctrl + 滾輪 | 縮放時間軸 |
| Ctrl + Z | 復原時間軸上的上一個操作 |
| Ctrl + Y／Ctrl + Shift + Z | 重做 |
| Ctrl + G | 跳到指定時間（也可以點目前時間的文字） |
| F1 | 快捷鍵一覽（也可以按時間軸工具列的「?」） |

按鈕可以用 Tab 移動焦點、Enter 按下；空白鍵與方向鍵即使焦點在按鈕上，仍然是播放與逐格。

## 與規格不同的決定

| 項目 | 規格 | 實作 | 原因 |
|---|---|---|---|
| .NET 版本 | .NET 8 | .NET 10 | .NET 8 於 2026-11-10 結束支援 |
| 切點參數 | `-ss` / `-to` 放在輸入之後 | `-ss` / `-t` 放在 `-i` 之前 | 重新編碼時同樣準確，而且不必從頭解碼 |
| 匯出進度 | 讀標準錯誤 | 讀 `-progress pipe:1` | 標準錯誤只用於錯誤訊息 |
| 編碼格式 | H.264 | 8-bit 用 H.264；10-bit 以上或 HDR 用 H.265 | H.264 一般是 8-bit，無法保留來源位元深度 |
| 音訊位元率 | 不低於來源 | 來源值，下限 192k、上限 512k | PCM 等高位元率來源超出 AAC 實務上限 |
| 畫質驗收 | 與來源無明顯差異 | 只比對未放大的情況 | 填滿裁切依解析度規則常需放大（1080p 來源為 1.78 倍） |

## 進度顯示

匯入素材、產生倒放預覽、匯出時，預覽畫面下方會出現進度面板（不會推動其他版面），工作結束後自動收起：

| 項目 | 顯示內容 |
|---|---|
| 讀取素材 | 第幾個／共幾個、檔名、目前步驟（讀取資訊／產生縮圖）、百分比 |
| 準備倒放預覽 | 百分比 |
| 匯出 | 檔名與解析度、百分比、預估剩餘時間、取消按鈕；完成後顯示「匯出完成」與花費時間約 4 秒。Windows 工作列圖示也會顯示匯出進度 |

## 規格未定義、由實作決定的行為

- **基準素材**：輸出解析度、影格率與色彩都以時間軸上第一個影片片段為準（圖片不算，見「圖片片段」）。片段不一致時，匯出前會提示。
- **原尺寸**：規格之外新增的比例選項，也是預設值。輸出沿用基準素材的長寬（奇數會調成偶數）；其他尺寸不同的片段依「處理方式」裁切或加黑邊。
- **不能匯入的檔案**：長度不到 0.1 秒（時間軸片段的最短長度）或讀不到長度的影片與音訊，以及動態 WebP，匯入時會提示失敗，同一批的其他檔案照常匯入。
- **圖片片段**：JPG、PNG、BMP、WebP、TIFF 可以匯入，放在影片軌（V1），預設 5 秒；圖片沒有入出點，加入後拖曳兩端調整長度（最短 0.1 秒、最長 1 小時，不對齊影格）。可以分割、旋轉鏡像、調整畫面位置，不能倒放，沒有聲音（A1 那段是靜音）。手機直拍照片會依 EXIF 方向轉正；透明的部分鋪黑。是不是圖片看檔案內容判斷，不看副檔名；動態 GIF 照影片處理。
  - **匯出**：圖片以基準影片的影格率重複成時間軸長度對應的格數，從 RGB 轉成影片時用與基準相同的色彩矩陣（預設 BT.709），顏色和影片一致。輸出的基準取第一個**不是圖片**的影片片段；時間軸全部是圖片時用 30 fps、H.264、BT.709，解析度以第一張圖為準、較大邊不超過 3840（手機照片原尺寸太大，很多播放器播不動）。圖片比輸出小、需要放大時，以及圖片放進 HDR 影片時（不做色調對應），匯出前會提醒。圖片只解碼、縮放一次再重複，大張照片也不會拖慢匯出。
  - **預覽**：圖片不交給 LibVLC，由 FFmpeg 解出一張顯示；播放、拖曳、逐格、倒帶經過圖片都顯示同一張，配樂照常播。播放中會先在背景解出接下來的兩張圖片。
- **軌道**：V1 放影片，A1 放影片原音並與 V1 連動（不可分離），A2 放配樂。
- **編輯規則**：同軌片段不可重疊，可留空白；拖曳不會推動其他片段。空白處輸出黑畫面與靜音。片段可以放在任意時間，但輸出的畫面只能是整數格，所以匯出時每個片段從它的位置最接近的那一格開始（最多差半格），誤差不會隨空白的數量累積。
- **入點與出點**：按 I／O 時，標記會對齊到畫面上正在顯示的那一格。片段包含入點那一格，但**不包含出點那一格**：出點標在哪一格，片段就播到它的前一格為止。想把目前看到的畫面也收進片段，要先往後移一格（→）再按 O。在時間軸上拖曳邊緣修剪也是同樣的規則。沒有標記時，入點是素材開頭、出點是素材結尾往下對齊到的整數格（素材長度常因為聲音比畫面長一點而不是整數格；最多少掉不到一格的尾端聲音）。
- **吸附**：拖曳片段時，離吸附點 8 像素以內會自動貼齊；按住 Alt 可暫時關閉所有吸附。吸附範圍以畫面像素計，時間軸放大時對應的秒數跟著變小。同時有好幾個吸附點在範圍內時取最近的，一樣近時依序為播放頭、片段邊緣、時間軸開頭、靜音處。
  - **移動片段**：片段的開頭或結尾貼齊播放頭、其他片段（兩軌都算）的開頭或結尾、時間軸開頭。吸到的位置與同軌片段重疊時，片段停到最近的空位，不算貼齊。工具列「吸附片段」取消時，移動完全不吸附。
  - **修剪片段邊緣**：貼齊播放頭、其他片段的邊緣（「吸附片段」取消時不吸）與靜音處（見下）。
  - **播放頭**：貼齊時播放頭變成黃色；貼齊片段邊緣或時間軸開頭時，在該位置畫一條貫穿所有軌道的黃線。
  - **靜音處**（工具列「吸附靜音」，預設開啟）：片段自己的聲音裡，峰值連續 0.25 秒以上低於 -40 dB 的段落算停頓（用原始聲音判斷，不受片段音量影響）。拉左緣停在聲音開始前 0.1 秒、拉右緣停在聲音結束後 0.1 秒，方便剪掉開頭結尾的空白；停頓短於 0.2 秒時（只會在素材頭尾）停在中間。倒放片段依時間軸方向計算。拖曳時該片段的音訊軌會把停頓塗暗，貼齊時畫一條黃線。需要波形已經產生好；還沒好或沒有音訊時只吸附播放頭。
  - 修剪後的切點會對齊來源影格（取最接近的一格，與 I／O 標記相同），所以吸附後邊緣與吸附點可能差不到一格；這樣畫面與聲音的長度才一致，接點不會多出靜音。0.1 秒的餘裕足以容納這個誤差。
- **聲音波形**：A1（影片原音）與 A2（配樂）片段上顯示波形，刻度為分貝（-48 dB 到 0 dB），高度已乘上片段音量；音量放大後超過 0 dB、匯出會破音的部分畫成紅色。倒放片段的波形左右相反。波形在匯入後於背景產生（一次一個素材，一小時的素材約十幾秒），還沒好時片段上註明「波形產生中」，不影響其他操作；只存在記憶體，關閉程式就清掉。
- **分割片段**：選取片段後按 S 或「在播放頭分割」，從時間軸播放頭的位置切成兩段，並選取右段。只在時間軸預覽時作用；播放頭要在選取的片段內。與 I／O 標記的規則相同，播放頭上正在顯示的那一格成為右段的第一格（純音訊照播放頭的時間切），兩段之間沒有空隙，匯出結果與分割前相同。音量、倒放、旋轉鏡像、畫面位置都沿用；倒放片段分割後播放不變。任一段短於 0.1 秒時不分割。
- **跳到剪輯點**：Page Up／Page Down。時間軸預覽時跳到影片軌片段的開頭與結尾（含時間軸開頭）；素材模式時在素材開頭、入點、出點、結尾之間跳。
- **配樂比影片長**：以黑畫面補到時間軸結束。
- **音量**：每段 0–200%，為線性增益；多聲道音訊混音為立體聲。
- **片段倒放**：選取影片軌片段後勾選「倒放這個片段」，畫面與原音一起倒放，位置與長度不變。配樂（A2）不能倒放。倒放片段的左緣是來源的出點、右緣是入點，修剪時依此調整。
- **倒放的匯出**：FFmpeg 的 `reverse` 濾鏡要把整段影格放在記憶體裡，所以每個倒放片段會切成多小段（每段解碼後約 512 MB 以內），每一小段各跑一次 FFmpeg、倒放後寫成無損的中間檔（FFV1 影像與 PCM 聲音），最後才由後往前接起來編碼。記憶體用量因此不隨片段長度增加（不能把所有小段放進同一個指令：各段會同時解碼，等於整段都在記憶體裡）。中間檔放在輸出檔旁邊的暫存資料夾（`檔名.xxxxxxxx.part.mp4.reverse`），匯出成功、失敗或取消後都會刪除；匯出前的磁碟空間提醒已計入它的大小。進度列涵蓋倒放與編碼兩個階段。可變影格率的素材（螢幕錄影、部分手機影片）會先把片段轉成固定影格率（素材的平均影格率）的中間檔再倒放：分段的切點是照影格率算的，影格間隔不固定時切不準；轉檔時快的段落會少掉一些影格、慢的段落會重複影格，暫存空間也多一倍。
- **倒放的預覽**：LibVLC 不能倒著播放，所以第一次播放到倒放片段時，會先在背景產生一個縮小的倒放預覽檔，產生完才繼續播放。時間軸每次編輯後都會同步：勾選倒放或修剪倒放片段後馬上開始產生新範圍的預覽檔，舊範圍（以及已刪除、取消倒放的片段）的預覽檔則停止產生並刪除。產生方式與匯出相同，逐小段倒放。預覽檔放在暫存資料夾，關閉程式時刪除；程式當掉而沒刪到的，下次啟動時清掉（同時開著的另一個程式正在用的不會動）。
- **旋轉與鏡像**：選取影片軌片段後，可左轉／右轉 90°、水平或垂直鏡像，預覽與匯出一致。順序固定為先旋轉、再鏡像；鏡像後再旋轉時，依畫面上看到的方向轉。像素比會在旋轉前修正。旋轉 90°／270° 的片段若是時間軸上第一個片段，「原尺寸」輸出會跟著變成直式；與其他片段方向不同時，匯出前會提示解析度不一致。旋轉以 `transpose` 搬移像素，不影響畫質。配樂（A2）沒有畫面，不適用。
- **畫面位置（填滿裁切）**：在剪輯預覽中，黃色的輸出框可以拖曳移動、拖曳四角縮放（維持輸出比例），也可以用滑鼠滾輪縮放、雙擊框重設，右側「畫面位置」也有重設按鈕。每個影片片段各自記錄，匯出時裁出同樣的範圍。框只能在畫面內移動，最小是最大框的 1/8（放大 8 倍）。位置以旋轉後的方向記錄，所以旋轉或鏡像片段時會回到預設（置中、最大）。加黑邊時不使用。有放大的片段會在片段清單與時間軸上標示「畫面 200%」（只移動位置時標示「畫面已移動」），匯出前也會提醒放大會讓畫質下降。
- **預覽模式標記**：預覽畫面有兩種模式，切換鈕為「匯入影片預覽」與「剪輯預覽」。匯入影片預覽顯示素材清單中選取的原始影片，可標記入出點；剪輯預覽顯示時間軸上的成品。畫面四周的色框與左上角的標籤會標明目前模式：藍色是匯入影片預覽（並顯示檔名），橘色是剪輯預覽。點素材清單裡的影片會自動切到匯入影片預覽；點時間軸上的片段（選取、拖曳、修剪）、尺規或空白處，或點右側片段清單，會自動切到剪輯預覽（點片段時播放頭不動）。用方向鍵在清單間移動時，只有素材清單換了選取才會切換。
- **快轉（L 或「▶▶ 快轉」）**：只用於預覽，不影響匯出。由 LibVLC 以倍速播放，按鈕在停止時直接從 2× 開始。2× 仍有聲音，4× 以上靜音。暫停、倒帶、拖曳播放頭都會回到正常速度。
- **匯出前的檢查**：輸出位置可寫入、不覆蓋來源、輸出檔能覆蓋，以及時間軸用到的素材檔都還在（找不到時列出檔名，提示確認外接磁碟或重新匯入）。ffmpeg 無法啟動（例如被防毒軟體擋下）時顯示說明，不跳出錯誤堆疊。匯出開始時會先確認這份 FFmpeg 含有要用的編碼器（libx264／libx265、aac，倒放時另需 ffv1），缺少時說明要換哪一種 FFmpeg，而不是顯示 FFmpeg 的原始錯誤。
- **磁碟空間的估算**：只是粗估，實際大小依畫面內容而定，所以空間可能不足時只會提醒、由你決定要不要繼續，不會擋下匯出；真的不夠時匯出會中途失敗，暫存檔會清掉。取兩種估法中較大的：來源位元率 × 1.5，以及依輸出解析度與影格率算出的重新編碼大小（H.264 每像素約 0.2 bit，1080p 30 fps 約 12 Mbps）。只看來源位元率的話，高壓縮的來源（例如手機的 HEVC）重新編碼後會被低估好幾倍。
- **匯出的暫存檔**：匯出時先寫到輸出資料夾裡「檔名.隨機碼.part.mp4」，完成才改成輸出檔名，不會碰到任何現有的檔案。影片做好但改名失敗時（例如匯出途中用播放器打開了舊的輸出檔），保留這個暫存檔並告知位置，不會丟掉做好的影片。
- **匯出中關閉視窗**：會先詢問是否確定關閉。確定時先取消匯出，等 FFmpeg 結束、暫存檔清掉後才關閉，不會在輸出資料夾留下半成品。
- **把素材拖到時間軸**：從素材清單拖曳素材到時間軸放下。放在片段的左半邊就插在它前面，右半邊（含正中間）插在它後面；同一軌後面的片段一起往後移，移動的距離等於新片段的長度，片段之間原本的空白不變。放在空白處時從放下的位置開始，放不下時後面的片段只往後移到剛好放得下。有畫面的素材放到 V1（原音在 A1 跟著移動），只有聲音的放到 A2；插入到 V1 時 A2 的配樂不動，所以配樂和畫面的對應位置可能改變（可以 Ctrl+Z 復原）。拖曳中會畫出插入線、新片段的位置與被推動片段移動後的位置；空白處靠近片段邊緣、播放頭或時間軸開頭時會貼齊（按住 Alt 或關閉「吸附片段」時不貼齊）。拖的是正在預覽的素材時，套用已標的入出點；拖別的素材時整段加入。從檔案總管直接拖檔案到時間軸，會先匯入再依同樣的規則放入（多個檔案依序接著放）；拖到視窗其他地方只匯入。這個規則只用在加入素材，拖曳移動時間軸上已有的片段仍然不推動其他片段。
- **雙擊素材**：和按「＋ 加入時間軸」相同，接在時間軸最後面。
- **移除素材**：在素材清單按右鍵「從清單移除」，或焦點在素材清單時按 Delete。時間軸上還有片段使用這個素材時不能移除，狀態列會說明。
- **時間軸右鍵選單**：在片段上按右鍵會選取它並切到剪輯預覽，選單有在播放頭分割、刪除、與前一段／後一段交換、倒放、旋轉鏡像、重設畫面位置、音量回到 100%（配樂片段只有適用的項目）；在空白處按右鍵有顯示全部與兩個吸附開關。
- **滑鼠游標**：片段邊緣是左右箭頭（修剪）、片段中間是手形（拖曳時變成四向箭頭）、時間尺是文字游標（點選時間）。
- **時間顯示**：預設是時間碼「時:分:秒:格」，格是這一秒裡的第幾格（29.97 fps 時是 0～29，時分秒照實際時間走，不做 drop-frame）。匯入影片預覽用該素材的影格率，剪輯預覽用輸出基準（時間軸第一個影片片段），時間軸是空的或是圖片時用 30 fps。按時間旁邊的「⇄」可以改成「時:分:秒.百分秒」，設定會記住。時間軸的時間尺在不到一秒的刻度也跟著顯示格數或小數。
- **輸入時間**：點目前時間（或按 Ctrl+G）、入點、出點的文字，會彈出輸入框。可以輸入 `65`、`1:05`、`1:05.5`、`1:02:03`、`00:01:05:12`、`120f`（第 120 格），或用 `+10`、`-2.5`、`+12f`、`-1:00` 從目前的值前後移動；全形數字與符號也可以。Enter 套用、Esc 取消。超出範圍時停在開頭或結尾並在狀態列說明；看不懂或格數超過影格率時外框變紅、說明原因，輸入框不關。跳過去的位置對齊到影格；入點、出點的規則和按 I／O 相同（入點要在出點之前）。圖片沒有入出點，不能輸入。
- **音量**：右側音量滑桿雙擊回到 100%；旁邊的輸入框可以直接打 0～200（Enter 或離開輸入框時套用，Esc 取消），下方顯示對應的分貝（「原音量」「+3.5 dB」「靜音」）。
- **匯出的檔名與資料夾**：預設檔名是「第一個片段的檔名_剪輯_年月日-時分.mp4」，不能用的字元換成底線，過長時截短。資料夾預設是上次匯出的資料夾，沒有的話用第一個片段所在的資料夾。匯出完成後，進度面板與狀態列都有「開啟資料夾」按鈕，會在檔案總管選取剛匯出的檔案。
- **復原與重做**：時間軸上的加入、刪除、分割、移動、修剪、調整順序、旋轉鏡像、畫面位置、倒放與音量都可以復原，最多 100 步。時間軸工具列有「↶ 復原」「↷ 重做」按鈕，滑鼠移上去顯示會復原哪個操作。拖曳音量滑桿、連續滾動滾輪縮放畫面位置，間隔 1 秒以內算同一步。素材清單、畫面比例與處理方式不在復原範圍內。新的修改會清掉可以重做的步驟。
- **時間軸有片段時關閉視窗**：目前不能存檔，所以會先提醒剪輯會遺失，預設選「否」。
- **狀態列**：視窗最下方固定一條狀態列，用圖示與顏色區分一般訊息、完成、警告與錯誤；訊息太長時滑鼠移上去可以看完整內容。
- **匯入失敗**：一次匯入的檔案中有好幾個讀不了時，全部處理完才合成一個對話框列出（每個檔案一行，完整錯誤在紀錄檔），不會連跳好幾個。
- **倒帶（J）**：只用於預覽，不影響匯出。由 FFmpeg 一次解出多格來顯示，沒有聲音；高倍速時每隔幾格才取一格。
- **逐格移動（← →）**：暫停時的畫面由 FFmpeg 解出。手機影片等關鍵影格間隔長的來源，每解一格都要從前一個關鍵影格解起，所以逐格移動時會連同同方向接下來的 12 格一起解，快用完前再於背景解下一批，連續按方向鍵時不必每一步都等。背景那一批還在解時若改去拖曳播放頭，會先中止它，優先解要顯示的那一格。

## 設定檔

關閉程式時，介面設定存到 `%LOCALAPPDATA%\VideoEditor\settings.json`，下次開啟時還原：視窗位置與大小（是否最大化）、素材清單與右欄的寬度、時間軸的高度（三條分隔線都可以拖曳）、吸附靜音與吸附片段的開關、畫面比例與處理方式、上次匯入與匯出的資料夾。時間軸與素材不會存（規格不含專案存檔）。設定檔損壞或讀不到時用預設值；存下的視窗位置已經不在任何螢幕上（例如拔掉外接螢幕）時，視窗回到預設位置。刪掉這個檔案就回到預設值。

## 紀錄檔

程式把錯誤寫進 `%LOCALAPPDATA%\VideoEditor\logs\app-yyyyMMdd.log`：未處理的例外、FFmpeg 失敗時的命令列與錯誤輸出尾段、匯出的開始與結果。每個檔案約 1 MB 換新檔，只保留最近 5 個。紀錄只存在本機，不會上傳；內容可能含檔案路徑（常有使用者名稱），回報問題前請先檢查。

## 已知限制

- **匯出的片段數量約 260 到 450 個以內**：每個片段的 `-ss -t -i 路徑` 都是 FFmpeg 命令列的一部分，整條命令列受 Windows 長度上限限制（程式以 30,000 字元估算）。素材路徑越長，上限越低（實測路徑 8 字元約 450 個、55 字元約 260 個）；超過時匯出前會顯示「片段數量過多」，不會當機。命令列太長時，濾鏡圖會改放進暫存檔再交給 FFmpeg（程式會先試跑確認這份 FFmpeg 支援 `-/filter_complex`，不支援就改用舊的 `-filter_complex_script`）。需要更多片段時，可以分成幾段匯出再接起來。
- **讀取素材資訊與解出影格有時間上限**（探測 2 分鐘、縮圖與單格 1 分鐘、倒帶批次 2 分鐘）：超過視為檔案損毀或磁碟卡住，會終止並顯示說明，匯入時可按「取消匯入」提早中止。
- 倒放片段匯出時需要暫存空間放無損中間檔，大小約為解碼後畫面的一半左右，依畫面內容而定：1080p 8-bit 每分鐘約 3 GB，4K 8-bit 每分鐘約 12 GB。很長的高解析度倒放片段要確認輸出磁碟的空間足夠。
- 倒帶播放的流暢度取決於 FFmpeg 解碼速度，長 GOP 的素材可能會跳格。
- 預覽切換片段時約有 0.1–0.3 秒停頓（LibVLC 載入時間），匯出不受影響。
- HDR 素材的預覽沒有做色調對應，顏色會偏淡；匯出會保留 HDR 標記。
- HDR 靜態中繼資料（mastering display）沒有明確保留。
- 不同色彩格式的片段接合時只統一格式，不做色調對應。
