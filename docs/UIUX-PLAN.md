# 介面與操作體驗（UI／UX）改善：規劃

2026-11-27 規劃，尚未實作。來源是對目前介面的靜態檢查（讀 `MainWindow.xaml`、`MainWindow.*.cs`、`TimelineView`、`ProgressOverlay`，沒有在 Windows 上實際操作），共 21 項，另外加上使用者要求的「用鍵盤輸入時間」（#22），依影響分成 7 個階段。每個階段可以單獨合併，前面的階段不依賴後面的。

## 一、要先確認的決定

下列幾項會改變規格或操作習慣，先照「建議」規劃；有不同意見請在實作前提出。

| # | 問題 | 建議 |
|---|---|---|
| 1 | 規格第 4 節把「專案存檔與復原／重做」列為非目標 | **只做復原／重做**，專案存檔仍不做。復原是剪輯時的安全網，範圍只限時間軸，不碰檔案格式。規格第 4 節改成「專案存檔」 |
| 2 | 拖曳素材到時間軸時，放下的位置和現有片段重疊怎麼辦 | **（2026-11-27 使用者決定）依照放在片段的哪一半，決定插入在它前面或後面**：放在片段的左半邊就插入在它前面，右半邊就插入在它後面。插入後，同一軌插入點之後的片段一起往後移，移動的距離等於新片段的長度，片段之間原本的空白維持不變。放在空白處時從放下的位置開始；放不下時，後面的片段只往後移到剛好放得下。這個規則只用在「加入素材」；拖曳移動時間軸上已有的片段，仍維持「不推動其他片段」 |

## 二、現況重點

- `OnClosing` 只在匯出中才確認；時間軸有片段時關閉視窗會直接遺失。
- 錯誤與提示幾乎都寫到 `StatusText`，它位在右側捲動面板的最底下。
- 右側一欄包含：畫面比例、處理方式、輸出資訊、片段清單、音量、旋轉鏡像、畫面位置、倒放、匯出。視窗高度最小是 640，這時匯出按鈕需要捲動才看得到。
- 片段的修改分散在多處：`Timeline` 的方法（`Append`、`Remove`、`Split`、`Move`、`TrimStart`、`TrimEnd`、`Swap`、`SetTransform`、`SetFraming`、`SetReversed`），音量則是直接設定 `clip.Volume`。
- 匯入失敗時，`ImportController` 每個檔案呼叫一次 `IImportView.ShowFailure`，畫面上每次都跳一個 `MessageBox`。
- 版面寬高都是固定值（左欄 250、右欄 280、時間軸 254），也沒有任何設定檔，每次開啟都回到預設值。
- 全部按鈕都是 `Focusable=False`；說明文字使用 `#777777`（在 `#1E1E1E` 背景上對比約 4:1）。

## 三、階段

### 階段 1：避免資料遺失、讓訊息看得到（#1、#3、#17）

**關閉前確認（#1）**
- `OnClosing`：沒有在匯出，但時間軸有片段時，詢問「時間軸上的剪輯會遺失（目前不支援存檔），確定要關閉嗎？」，預設選項是「否」。
- 匯出中的確認維持現狀。兩種情況同時成立時，只問一次（使用匯出中的訊息）。

**固定的狀態列（#3）**
- `MainWindow.xaml` 新增最下方一列（`Height="Auto"`），放狀態文字。右側面板裡的 `StatusText` 移除。
- 新增 `ShowStatus(string message, StatusKind kind)`，`kind` 分成一般、警告、錯誤三種，用顏色與圖示（ⓘ／⚠／✖）區分。程式中現有的 `StatusText.Text = …` 都改用這個方法。
- 狀態列右側固定顯示正在使用的 FFmpeg 版本，不再和其他訊息搶同一個位置。

**匯入失敗彙整（#17）**
- `IImportView.ShowFailure(name, message)` 改成 `ShowFailures(IReadOnlyList<ImportFailure>)`，在一批檔案全部處理完後才呼叫一次。
- 只有一個檔案失敗時，訊息和現在相同；多個檔案失敗時，用一個對話框列出「檔名：第一行錯誤」，完整的錯誤輸出寫在紀錄檔。
- 測試：`ImportControllerTests` 的假 View 配合修改，新增「多個檔案失敗只回報一次，而且依照匯入順序」。

### 階段 2：復原／重做（#2）

**Core：`Editing/TimelineHistory.cs`**
- `Timeline.Capture()` 回傳 `TimelineSnapshot`，內容是兩軌各片段的參照與狀態（`SourceIn`、`SourceOut`、`Start`、`Volume`、`Reversed`、`Transform`、`Framing`）以及順序。`Timeline.Restore(snapshot)` 寫回狀態並重建兩軌的清單。
  - 保留同一個 `TimelineClip` 物件（不是複製一份），這樣選取狀態、波形快取、倒放預覽快取都不受影響。
- `TimelineHistory`：`Record(string label)` 在修改**之前**呼叫；提供 `Undo()`、`Redo()`、`CanUndo`、`CanRedo`、`UndoLabel`。最多保留 100 步，新的修改會清掉可以重做的部分。
- 連續修改合併成一步：`Record(label, mergeKey)` 的 `mergeKey` 和上一步相同時不新增，用於拖曳音量滑桿、滾輪縮放畫面位置。

**要記錄的操作**：加入、刪除、分割、移動、修剪（`TimelineView.EditStarted`）、交換順序、旋轉鏡像、畫面位置（拖曳開始、滾輪、重設）、倒放、音量。

**App**
- Ctrl+Z 復原，Ctrl+Y 或 Ctrl+Shift+Z 重做。`OnPreviewKeyDown` 目前一遇到組合鍵就跳過，所以要在那個判斷之前處理；焦點在文字框時不攔截。
- 復原或重做後呼叫 `OnClipsChanged()`；如果原本選取的片段還在時間軸上就維持選取，不在了就取消選取。狀態列顯示「已復原：分割片段」。
- 時間軸工具列加上「↶ 復原」「↷ 重做」按鈕，不能用時停用，滑鼠移上去顯示要復原的動作名稱。

**測試**：每一種操作做完再復原，都回到原本的狀態；復原後重做回到修改後的狀態；連續修改會合併；最多 100 步；復原後 `TimelineClip` 仍是同一個物件。

### 階段 3：重整右側面板（#4、#5、#9）

右欄改成兩塊：

```
┌ 輸出 ───────────────┐   固定在上方，不捲動
│ 畫面比例  處理方式   │
│ 輸出解析度與編碼     │
│ [ 匯出 MP4… ]        │
├ 片段 ───────────────┤   下方可捲動
│ 片段清單（影片軌）   │
│ ─ 選取的片段 ─       │
│ 音量／旋轉鏡像／     │
│ 畫面位置／倒放       │
└─────────────────────┘
```

- 「選取的片段」這一區包成 `ClipPropertiesPanel`（一個 `StackPanel`）。沒有選取片段時整區隱藏，改顯示「點時間軸上的片段來調整音量、旋轉與畫面位置」（#5）。
- 選取的是 A2 配樂片段時，只顯示音量。
- 「畫面位置」只在處理方式是「填滿裁切」時顯示；選「加黑邊」時隱藏，而不是留著一個灰色按鈕。
- 片段清單拿掉「上移／下移」（#9，見決定 4）；`Timeline.Swap` 與 `OnMoveUp`／`OnMoveDown` 如果沒有其他地方使用就一起刪除，測試配合修改。
- 「刪除」「在播放頭分割」移到時間軸工具列（階段 5 的右鍵選單也會有）。

### 階段 4：播放列與版面（#6、#7、#19、#21）

**播放控制列（#6）**
- 分成三組，中間加 `Separator`：播放（倒帶、播放、快轉、前一格、後一格）｜標記（入點、出點、入出點文字）｜加入時間軸。用 `StackPanel` 加上固定間距，取代 `WrapPanel`，避免換行位置無法預期。
- 「匯入影片預覽／剪輯預覽」從播放列移到預覽區上方，改成兩個並排的切換鈕，顏色和左上角的模式標籤（藍／橘）一致。

**可以調整的版面（#7）**
- 加上三條 `GridSplitter`：左欄與預覽之間、預覽與右欄之間、上方與時間軸之間。
- 最小值：左欄 200、右欄 260、預覽 400 寬、時間軸 210 高（時間尺加上三軌、工具列、捲軸）。

**記住設定（#19）**
- Core 新增 `Settings/AppSettings.cs`（record）與 `SettingsStore`，存成 `%LOCALAPPDATA%\VideoEditor\settings.json`，和紀錄檔放在同一個資料夾。
- 儲存的項目：視窗位置、大小與是否最大化，三條分隔線的位置，吸附靜音與吸附片段的開關，畫面比例與處理方式，時間顯示格式，上次匯入與匯出的資料夾。
- 檔案損壞或讀取失敗時使用預設值並寫一筆警告，不能讓程式打不開。視窗位置不在任何螢幕範圍內時（例如外接螢幕已拔掉），回到螢幕中央。
- 在 `OnClosed` 儲存；寫入時先寫暫存檔再取代，避免寫到一半的檔案。
- 測試：讀寫來回一致、檔案損壞時用預設值、未知欄位會忽略、缺少的欄位用預設值。

**時間軸空白時的提示（#21）**
- `TimelineView.OnRender`：沒有任何片段時，在軌道區域中央畫出「選素材後按『加入時間軸』，或直接把素材拖到這裡」。

### 階段 5：時間軸與素材的操作（#8、#10、#11、#12）

**把素材加入時間軸（#8）**
- 雙擊素材清單的項目，效果等同按「加入時間軸」。
- 從素材清單拖曳到時間軸：
  - `MediaList` 用 `DoDragDrop` 拖出 `MediaItem`。`TimelineView` 設定 `AllowDrop`，在 `DragOver` 依照素材種類（有畫面的放 V1、純音訊的放 A2）畫出預定位置的半透明框，套用和移動時相同的吸附規則。
  - 放下的位置照決定 2 處理。目前在素材預覽中標記的入出點會套用到拖曳的素材。
  - **拖曳中的提示**：游標在片段上時，在要插入的那一側邊緣（左半邊顯示在片段開頭，右半邊顯示在片段結尾）畫一條強調色的插入線，並顯示「插入到 ○○ 前面／後面」。游標在空白處時，畫出新片段會佔的半透明框；如果放下後會把後面的片段往後推，被推動的片段也畫出移動後的位置。
  - **左右半邊的判斷**：以片段在畫面上的中點為界；正好在中點時算後面。片段非常短（畫面上不到 16 像素）時，也一樣用中點判斷。
  - **吸附**：游標在空白處時套用和移動時相同的吸附規則（片段邊緣、播放頭、時間軸開頭）；游標在片段上時直接使用片段的邊緣，不需要吸附。
  - **配樂不會跟著移動**：插入到 V1 時，V1 的片段（包括它們在 A1 的原音）往後移，但 A2 的配樂不動；插入到 A2 時只移動 A2。所以插入後，配樂和畫面的對應位置可能會改變，狀態列會提示「已插入，後面 N 個片段往後移 X 秒」，需要的話可以用 Ctrl+Z 復原。
  - Core：`Timeline.Insert(media, sourceIn, sourceOut, track, start)` 在 `start` 插入，並把同軌 `Start ≥ start` 的片段往後移到不重疊為止。`TimelineEditor.AddAt(media, points, dropTime)` 先用 `InsertTarget(track, dropTime)` 算出插入位置（落在片段上時，依照左右半邊回傳該片段的開頭或結尾；落在空白處時回傳 `dropTime`），再呼叫 `Insert`，回傳 `AddResult`（多帶「往後移的片段數與秒數」，給狀態列使用）。
  - 測試：放在片段左半邊插入到前面、右半邊插入到後面、正好在中點算後面；後面的片段整批往後移，原本的空白維持不變；放在空白處而且放得下時，其他片段都不動；放在空白處但放不下時，後面的片段只移剛好的距離；插入到 V1 時 A2 不動；入出點有套用；圖片使用 5 秒；可以復原。
- 從檔案總管拖到時間軸：先匯入再放到放下的位置。拖到視窗其他地方則維持現在的行為（只匯入）。

**移除素材（#10）**
- 素材清單加右鍵選單「從清單移除」；焦點在素材清單時按 Delete 也是移除（`OnPreviewKeyDown` 依照 `OriginalSource` 判斷，不刪除時間軸片段）。
- 時間軸上還有片段使用這個素材時照決定 5 處理。移除後如果是目前預覽的素材，就清空預覽。

**時間軸右鍵選單（#11）**
- 右鍵先選取游標下的片段，再顯示選單：在播放頭分割（S）、刪除（Delete）、倒放（可勾選）、左轉 90°、右轉 90°、水平鏡像、垂直鏡像、重設畫面位置、音量回到 100%。
- 不適用的項目停用，判斷規則和右側面板相同（例如圖片不能倒放、配樂只有音量）。在空白處按右鍵只顯示「顯示全部」與兩個吸附開關。

**游標（#12）**
- `TimelineView.OnMouseMove`：滑鼠在片段中間顯示 `Cursors.Hand`，拖曳移動時顯示 `Cursors.SizeAll`，在時間尺上顯示 `Cursors.IBeam`，在邊緣維持現在的 `SizeWE`。

### 階段 6：細節與輸入時間（#13～#16、#18、#20、#22）

**音量（#13）**
- 雙擊滑桿回到 100%。
- 右邊的百分比改成可以輸入的文字框（0–200，按 Enter 或離開時套用，不合法的值恢復原值），旁邊顯示 dB，例如「150%（+3.5 dB）」。
- 換算 dB 的函式放在 Core 並寫測試；0% 顯示「靜音」。

**時間碼（#14）**
- `PlaybackText.Timecode(seconds, fps)` 回傳 `時:分:秒:格`；fps 是 0（圖片）時使用 30。
- 素材預覽用該素材的影格率；剪輯預覽用輸出基準（`ExportPlanner.Reference`），時間軸是空的時用 30。
- 套用在 `TimeText`、入出點文字，以及時間尺（刻度間距小於 1 秒時才顯示格數）。
- 測試：29.97／30／25／60 fps 的進位、結尾那一格、負值。

**用鍵盤輸入時間（#22）**
- **跳到指定時間**：點一下 `TimeText`（目前位置），或按 Ctrl+G，時間文字就變成輸入框，並選取全部文字。輸入時間後按 Enter 跳過去，按 Esc 或點別的地方則取消。
  - 素材預覽：跳到素材中的位置，對齊到該素材的影格（`InOutPoints.Snap`）。
  - 剪輯預覽：移動時間軸播放頭，對齊到輸出基準的影格。
- **直接輸入入點與出點**：點入出點文字中的 `I …` 或 `O …`，同樣變成輸入框。輸入後設定入點或出點，並把預覽移到那一格。規則和按 I／O 相同：出點不能早於入點，不合法時狀態列說明原因並保留原值；圖片沒有入出點，所以停用。
- 輸入框打開時，按鍵都交給輸入框（`OnPreviewKeyDown` 已經會跳過 `TextBoxBase`），所以輸入數字或 `:` 不會觸發快捷鍵。
- 無法解析的文字：輸入框外框變紅，並在狀態列顯示可以接受的格式，不關閉輸入框。
- **Core**：`Playback/TimecodeParser.Parse(text, fps, current)` 回傳秒數或錯誤訊息，只負責解析，不知道任何控制項。
  - 接受的格式照決定 7。`:` 和全形 `：`、`.` 和全形 `．` 都可以使用，前後空白會忽略。
  - 格數超過該影格率時視為錯誤（例如 30 fps 時輸入 `:30`）；fps 是 0（圖片）時使用 30。
- **測試**：每一種格式；29.97／25／60 fps 的格數換算；相對時間的正負；全形符號；空字串、`1::2`、負的絕對時間、超出格數這類錯誤輸入；和 `PlaybackText.Timecode` 來回轉換後結果一致。

**快捷鍵說明（#15）**
- 按 F1 或時間軸工具列的「?」按鈕，開啟快捷鍵一覽（一個小視窗，分成播放、標記、編輯、時間軸、復原五組）。
- 一覽表的內容和 `PreviewKeys` 放在同一處定義，避免文件和實際行為不一致。
- 一覽表也列出 Ctrl+G（跳到指定時間）。
- 時間軸工具列上那行會被截斷的提示改成「F1：快捷鍵」。

**對比與字級（#16）**
- `Palette` 新增 `TextSecondary`（`#B0B0B0`）與 `TextDim`（`#9A9A9A`），取代 XAML 中的 `#777777`、`#9A9A9A`、`#B0B0B0`。
- 最小字級改為 12（素材摘要原本是 11）；`TimelineView` 的片段文字維持 11，但改用比較亮的顏色。
- 目標：一般文字和背景的對比至少 4.5:1（WCAG AA）。

**匯出（#18）**

## 四、需要在 Windows 上手動驗證

這個專案的 UI 沒有自動化測試，下列項目要實際操作確認：

- 關閉確認的三種情況：空白時間軸、有片段、匯出中。
- 每一種操作都能復原與重做，預覽畫面也會跟著更新（包括倒放與畫面位置）。
- 視窗高度最小（640）時，匯出按鈕不需要捲動就看得到。
- 分隔線拖曳，關閉後重新開啟，位置都有保留。
- 拖曳素材到時間軸：放在片段的左半邊與右半邊、放在第一個片段前面與最後一個片段後面、放在放得下與放不下的空白處、放純音訊素材到 A2、從檔案總管拖入；拖曳中的插入線與被推動片段的預覽位置都正確，復原後回到插入前的狀態。
- 焦點在各種按鈕上時，空白鍵、方向鍵、J／K／L、I／O、S、Delete 的行為都和以前一樣。
- 輸入時間：素材預覽與剪輯預覽各試一次絕對時間與相對時間；輸入入點、出點；輸入框打開時按空白鍵、I、S 不會觸發快捷鍵。
- 高 DPI（150%）下，焦點外框、游標與右鍵選單都正常。
