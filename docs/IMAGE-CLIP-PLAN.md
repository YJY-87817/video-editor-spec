# 圖片片段與預覽切換：規劃

2026-11-24 規劃，尚未實作。兩件事一起規劃：

1. **圖片片段**（第一～六節）：讓 JPG、PNG 等靜態圖片可以匯入，當成一段片段放在影片軌（V1），和影片片段一樣拖曳、修剪、分割、調整畫面位置，匯出時顯示成一段靜止畫面。適合把照片串成影片，或在影片前後加上片頭、片尾圖。
2. **點哪裡就預覽哪裡**（第七節）：點匯入影片區時，預覽自動切到「匯入影片預覽」；點時間軸或片段清單時，自動切到「剪輯預覽」。

## 一、決定（2026-11-24 與使用者確認）

| # | 問題 | 決定 |
|---|---|---|
| 1 | 圖片怎麼放進影片 | 當成片段放在影片軌（V1），佔一段時間、全畫面顯示。疊在影片上面的圖片（子母畫面、浮水印、貼圖）不在這次範圍 |
| 2 | 加到時間軸時的長度 | 5 秒，之後可拖曳修剪成任意長度 |
| 3 | 動態效果（慢慢放大、平移） | 這次不做，只有靜止畫面；屬於規格的「特效」，之後另外規劃 |

## 二、依現有規則推得的細節（有不同意見請提出）

這些沒有逐一詢問，是照專案已有的規則推出來的：

**匯入**
- **支援格式**：JPG／JPEG、PNG、BMP、WebP、TIF／TIFF。選檔對話方塊加上這些副檔名，拖放也接受。HEIC 不支援（一般 FFmpeg 組建讀不了），匯入時照現有方式顯示錯誤。
- **怎麼判斷是圖片**：看 ffprobe 的結果，不看副檔名：容器是 `image2` 或 `*_pipe`（如 `png_pipe`），而且影像編碼是圖片格式（mjpeg、png、bmp、webp、tiff）。動態 GIF、動態 WebP 不算圖片，照現在的方式當影片處理（或被擋下）。
- **手機直拍照片的方向**：JPEG 的 EXIF 方向在 ffprobe 的串流資訊裡讀不到，只出現在影格資訊裡（實測 FFmpeg 6.1.1：`-show_streams` 沒有，`-show_frames` 有 `rotation: -90`），但 FFmpeg 解碼時會自動轉正。所以圖片要多讀第一格的資訊，顯示尺寸照轉正後的方向記錄，否則直拍照片會被當成橫的來算比例與畫面位置。
- **素材資訊**：素材清單顯示「圖片　寬×高」，不顯示長度、影格率、音訊。

**素材預覽（尚未加入時間軸時）**
- 顯示圖片本身，沒有播放與進度條可拖；入點、出點（I／O）不作用。
- 「加入時間軸」直接接一段 5 秒的片段到影片軌尾端。

**時間軸**
- **修剪**：圖片沒有來源長度的限制，左右兩緣都能拉長或縮短，只受相鄰片段與最短 0.1 秒限制。上限 1 小時（防呆，避免拉出極長的片段）。
- **對齊**：圖片沒有自己的影格，修剪與分割照時間切；匯出時已經會把每段對齊到輸出的影格（現有的 `GridFrame`），不需要另外處理。
- **分割（S）**：可以，兩段都是同一張圖。
- **倒放**：圖片倒放沒有意義，按鈕停用。
- **旋轉、鏡像、畫面位置（填滿裁切時拖曳縮放）**：都可以用，規則與影片片段相同。
- **音量**：圖片沒有聲音，滑桿停用（和沒有音訊的影片片段相同）。A1 那一段是空白，匯出時補靜音（現有規則）。
- **時間軸上的外觀**：片段上顯示圖片縮圖，顏色和影片片段區分（例如不同底色），一眼看得出是圖片。

**預覽（時間軸）**
- 播放到圖片片段時，畫面顯示 FFmpeg 解出的那一張圖（只解一次、放進快取），不交給 LibVLC 播放；播放時鐘照常走，配樂照常播。
- 拖曳播放頭、逐格移動、倒帶（J）、快轉（L）經過圖片時都顯示同一張圖。

**匯出**
- **圖片的畫面**：以 `-loop 1 -framerate <輸出影格率> -t <長度> -i 圖片` 讀入，輸出的格數與時間軸長度一致（實測 2 秒 × 29.97 fps 得到 60 格）。之後和影片片段一樣經過旋轉鏡像、畫面位置、填滿裁切或加黑邊。
- **透明 PNG**：透明的地方鋪黑底，和加黑邊的黑色相同。
- **色彩**：圖片是 sRGB（RGB 格式），轉成影片的 YUV 時明確指定 BT.709 的轉換方式並標記。不指定時 FFmpeg 預設用 BT.601，和一般影片放在一起顏色會偏。
- **基準素材**（輸出解析度、影格率、編碼格式、色彩）：規格是「時間軸第一個影片片段」。圖片沒有影格率、位元深度與色彩資訊可以沿用，所以改成**第一個不是圖片的影片片段**。
  - 時間軸全部都是圖片時：影格率 30 fps、H.264 8-bit、BT.709；解析度以第一張圖為準，但較大邊不超過 3840（4K），因為手機照片常是 4000～8000 像素，直接當輸出解析度太大，很多播放器播不動。
  - 基準影片片段是 HDR 或 10-bit 以上時，圖片照 SDR 放進去、不做色調對應，顏色可能偏淡；沿用現有「片段色彩格式不一致」的警告。
- **畫質**：圖片比輸出小時會被放大，沿用現有「放大會降低畫質」的警告方式，提示哪幾段圖片解析度不足。

## 三、現況

- `MediaProbe.Parse` 會擋下靜態圖片：ffprobe 讀到的長度約 0.04 秒（JPG）或讀不到（PNG、WebP、BMP），錯誤訊息是「可能是靜態圖片」。
- `MediaInfo` 沒有「這是圖片」的欄位；`FrameRate` 對圖片會讀到 25/1（ffprobe 的預設值，不是真的影格率）。
- `Timeline.TrimStart`／`TrimEnd` 以 `Media.Duration` 與 `SourceIn`／`SourceOut` 限制可拉長的範圍；`Append` 檢查 `sourceOut ≤ Media.Duration`。
- `PreviewEngine.UpdateVideo` 一律交給 LibVLC 播放，並等第一格出現才讓時鐘繼續走（`_waitingForFirstFrame`）；`FollowVideoClock` 以 LibVLC 的進度校正時鐘。
- `ExportPlanner.Build` 的基準素材是 `clips[0].Media`；每個片段以 `-ss -t -i` 讀入。
- `ImportController.LoadThumbnailAsync` 在 `min(1, 長度/10)` 秒取縮圖，對圖片會取在 0 秒附近，可以沿用。

## 四、設計

### 1. 素材資訊（Core：`MediaInfo`、`MediaProbe`）

- `MediaInfo.IsStill`：是否為靜態圖片。圖片的 `HasVideo = true`、`HasAudio = false`、`FrameRate = 0/1`、`Duration = Timeline.MaxStillDuration`（1 小時，讓時間軸不用另外處理「來源長度」）。
- `MediaProbe.Parse(json, path)`：依第二節的規則判斷圖片；是圖片時不檢查最短長度，並從影格資訊讀 EXIF 旋轉角度，換算轉正後的顯示尺寸。
- `MediaProbe.ProbeAsync`：參數加上 `-show_frames -read_intervals %+#1`（只讀第一格），JSON 裡多一個 `frames` 陣列。影片也會多讀一格的資訊，花費很小；或先讀一次、判斷是圖片才再讀一次，在階段 1 實測後決定。

### 2. 時間軸（Core：`Timeline`、`TimelineEditor`）

- `Timeline.StillClipDuration = 5`、`MaxStillDuration = 3600`。
- `Timeline.Append`：圖片固定 `SourceIn = 0`、`SourceOut = 長度`。
- `TrimStart`／`TrimEnd`：圖片的「可用來源」視為無限（只受相鄰片段、最短長度、上限 1 小時限制）；`SourceIn` 維持 0，只改 `SourceOut`（長度）與 `Start`。
- `SetReversed`：圖片丟出 `ArgumentException`（畫面上按鈕本來就停用，這是防呆）。
- `Split`：圖片走「沒有影格率、照時間切」的現有分支，右段 `SourceIn` 也歸 0。
- `TimelineEditor.Add(media, points)`：圖片忽略入出點，加 5 秒。

### 3. 預覽（App：`PreviewEngine`；Core 可測的部分放 `Playback`）

- `UpdateVideo` 遇到圖片片段：停止 LibVLC 影片播放器、以 `FrameExtractor.ExtractAsync(path, 0, size)` 取圖（快取鍵用 `(path, 0)`）、顯示後不設 `_waitingForFirstFrame`，時鐘直接走；`FollowVideoClock` 在圖片片段上不校正。
- 暫停、拖曳、逐格、倒帶顯示影格的路徑：圖片一律取第 0 格。
- 素材模式選到圖片：顯示圖片，進度條與 I／O、播放按鈕停用。

### 4. 匯出（Core：`ExportPlanner`）

- 基準素材：`clips.FirstOrDefault(c => !c.Media.IsStill)`；沒有時依第二節的「全部都是圖片」規則（`OutputSize` 加上長邊上限參數）。
- 圖片片段的輸入：`-loop 1 -framerate <基準影格率> -t <長度> -i 路徑`，濾鏡開頭加上「鋪黑底、轉 BT.709」，之後接 `FitFilter`，其他（concat、音訊補靜音）沿用。
- `keepTimestamps`：只看影片片段；圖片已經以基準影格率產生，不需要 `fps` 濾鏡。
- 警告：圖片放大的提示；`CollectWarnings` 的影格率、解析度、色彩比較略過圖片。

### 5. 畫面（App）

- 匯入對話方塊的篩選加上圖片副檔名。
- 素材清單、素材資訊顯示「圖片」。
- 片段面板：圖片片段停用倒放與音量。
- `TimelineView`：圖片片段的底色與縮圖。

## 五、實作階段

| 階段 | 內容 | 驗證 |
|---|---|---|
| 1 | 匯入與素材資訊 | 單元測試：JPG、PNG、BMP、WebP、TIFF 的 ffprobe JSON 判斷為圖片，尺寸、旋轉正確；EXIF 方向 6、8（含鏡像的 2、4、5、7 實測後決定）；動態 GIF 不算圖片；一般影片不受影響。整合測試：實際 ffprobe 讀測試圖片 |
| 2 | 時間軸規則 | 單元測試：加入為 5 秒、忽略入出點；兩緣都能拉長、不超過相鄰片段與 1 小時；分割；不能倒放；旋轉與畫面位置照常 |
| 3 | 匯出 | 整合測試：圖片片段的影格數與長度；圖片接影片、影片接圖片；全部圖片時的影格率與解析度上限；透明 PNG 鋪黑；直拍照片轉正；色彩（純色圖片匯出後的 YUV 值符合 BT.709）；填滿裁切與加黑邊 |
| 4 | 預覽與畫面 | Windows 上手動驗證（見下） |
| 5 | 文件 | README 操作說明、`video-editor-spec.md` 4.1 |

需要在 Windows 上手動確認：
- 拖入照片、直拍照片、透明 PNG，素材清單與預覽正確。
- 圖片片段在時間軸上拖曳、修剪、分割；播放經過圖片時畫面切換順、配樂不中斷；拖曳播放頭、逐格、J／L 經過圖片正常。
- 匯出後的影片中，圖片顯示的時間、方向、顏色與預覽相同。

## 六、風險與待確認

- **EXIF 鏡像方向**（2、4、5、7）：FFmpeg 6.1 的自動轉正是否處理鏡像要實測；不處理的話，改成自己讀出方向、套用到片段的 `FrameTransform`。
- **大圖的預覽速度**：數千萬像素的照片每次解碼較慢，所以預覽只解一次並快取；縮圖與預覽尺寸沿用現有的上限。
- **專案存檔尚未實作**：這次不影響；之後做存檔時，圖片片段要記錄 `IsStill` 與長度。

## 七、操作修正：點哪裡就預覽哪裡

### 1. 需求（2026-11-24 使用者提出）

- 點左側的匯入影片區（素材清單），預覽畫面自動變成「匯入影片預覽」，顯示那支影片。
- 點下方的剪輯時間軸，預覽畫面自動變成「剪輯預覽」，顯示剪好的結果。

### 2. 現況（哪些情況沒有自動切換）

預覽區上方有「匯入影片預覽／剪輯預覽」兩個選項，目前只有部分操作會自動切換：

| 操作 | 現在 | 修正後 |
|---|---|---|
| 素材清單點**另一支**影片 | 切到匯入影片預覽（`OnMediaSelected`） | 不變 |
| 素材清單點**已經選取的那支**影片 | 不切換（清單的選取沒變，`SelectionChanged` 不會觸發） | 切到匯入影片預覽 |
| 時間軸點尺規或空白處 | 切到剪輯預覽，播放頭移到點的位置（`OnTimelinePlayheadDragged`） | 不變 |
| 時間軸點**片段**（選取、拖曳、修剪） | 不切換 | 切到剪輯預覽 |
| 右側片段清單點片段 | 不切換 | 切到剪輯預覽 |

最常遇到的情況：在剪輯預覽時想回去看剛才那支素材，點它沒有反應，只能去點上方的選項；在匯入影片預覽時拖曳時間軸上的片段，預覽畫面卻還是素材。

### 3. 依現有規則推得的細節（有不同意見請提出）

- **已經在對的模式時不重新載入**：例如剪輯預覽正在播放，再點時間軸上的片段，不會停下或跳回去。
- **點片段時播放頭不動**：點片段多半是為了選取或拖曳，播放頭跳走反而干擾；只切換預覽模式，畫面顯示目前播放頭位置的成品。要看某一段，照現在的方式點尺規或用 Page Up／Page Down。
- **切回匯入影片預覽時保留入出點**：點的是同一支影片時，已標記的 I／O 保留（現在切換模式就不會清掉）；點另一支影片時照現在的規則清掉。
- **素材清單的空白處**：沒有點到任何影片時不切換，因為沒有東西可以預覽。
- **時間軸左側的軌道名稱欄**：不切換（那裡不是時間軸的內容）。
- **鍵盤操作不在範圍內**：用方向鍵在清單間移動，維持現在「選取改變才切換」的行為。

### 4. 設計（App）

- `MediaList`：加上 `PreviewMouseLeftButtonUp`，點到的是影片項目（以 `ItemsControl.ContainerFromElement` 判斷），且目前在剪輯預覽時，切到匯入影片預覽（`SourceMode.IsChecked = true`）。選取改變的情況維持由 `OnMediaSelected` 處理，不重複載入。
- `TimelineView`：新增 `ClipPressed` 事件，在 `OnMouseLeftButtonDown` 點到片段時觸發；`MainWindow` 收到後呼叫 `SwitchToTimelinePreview()`。
- `ClipList`：`OnClipListSelected` 由使用者點選時（不是程式同步選取，`_clipListGuard` 未啟動）呼叫 `SwitchToTimelinePreview()`；點已選取的那一列也要切換，同樣用 `PreviewMouseLeftButtonUp` 處理。
- `SwitchToTimelinePreview()` 與切回匯入影片預覽都只在模式不同時才改 `IsChecked`，所以「已經在對的模式時不重新載入」不需要另外判斷。

### 5. 實作與驗證

這部分與圖片片段無關、改動小，建議**先做**，放在圖片片段的階段 1 之前。全部是畫面操作，在 Windows 上手動驗證：

- 剪輯預覽中點素材清單裡已選取的影片，切到匯入影片預覽，入出點還在；點另一支影片，切過去並清掉入出點。
- 匯入影片預覽中點時間軸上的片段、拖曳或修剪片段、點右側片段清單，都切到剪輯預覽，播放頭不動。
- 剪輯預覽播放中點時間軸片段，播放不中斷。
- 點素材清單空白處、時間軸左側軌道名稱，不切換。
